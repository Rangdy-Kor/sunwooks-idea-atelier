## 인터페이스 / 디자인

---

### Noto Font 통합

---

Windows 기본 폰트가 다국어 지원의 통일성 저하를 해결하기 위해 Noto 시리즈로 통합된다. 맑은 고딕, Segoe UI 등 레거시 폰트들은 하위 호환성을 위해 폴백 폰트로 내장되나, 더 이상 기본 폰트로 사용되지 않는다. 시스템과 인터페이스에는 Noto Sans, 워드프로세서 등의 문서에는 Noto Serif, 터미널과 IDE, 에디터에는 Noto Sans Mono가 기본으로 사용된다.

### LucidType

---

디스플레이의 폰트 가독성 향상 기술이 기존 서브 픽셀 렌더링 방식의 ClearType에서 새로운 Lucid Type으로 변경된다. 서브 픽셀 렌더링 방식이 FHD 이상의 해상도에서 유의미한 가독성 향상 효과를 보여주지 못하였기에, LucidType은 차세대 그레이스케일 안티 앨리어싱 기술을 사용하며, 사용자의 모니터 해상도에 따라 동적으로 강도가 조절된다. 단, HD 이하의 해상도에서는 ClearType이 자동으로 적용된다.

### Bubble UI

---

Fluent Design의 새로운 디자인 형식으로 Bubble UI가 추가된다. 기존의 평면적인 UI에서 대중이 심심함을 느낀다는 점에서 고안된 Bubble UI는 화면 내부에서 입체감과 시인성을 더한 원형 / 알약 형태의 UI로 발전되었다. 적용 범위와 사례는 아래에 기재되어 있다.

- **네비게이션 버튼**: 창 우측 상단의 네비게이션 버튼 (최소화, 최대화, 창 닫기)의 위치가 제목 표시줄에서 창 내부로 이동함과 동시에, 원형 플로팅 Bubble UI로 변경된다. 기존처럼 호버 등의 특정 트리거 없이도 클릭만으로 창을 조절할 수 있으며, 형태만 원형으로 바뀌었을 뿐 상호작용 판정은 이전의 사각형 네비게이션 버튼과 동일하다.
- **작업 표시줄**: 하단의 작업 표시줄이 기존 수평 전체를 차지하는 바에서 플로팅 알약 형태로 변한다. 검색 상자와 시스템 트레이, 위젯은 작업 표지술에서 다른 위치로 이동하며, 바탕화면 보기 막대는 예외적으로 최우측 하단에 독립된 기존 위치에 분리된다. 창을 최대화하거나 타일링 시 좌우로 펼쳐지는 애니메이션과 함께 기존 작업 표시줄처럼 바 형태로 변한다. 이는 최대화 및 타일링 시 작업 표시줄의 공백에 비쳐지는 바탕화면에 불편함을 느끼는 사용자들이 유의미하게 많다는 점에서 고안되었으며, 접근성 설정에서 비활성화할 수 있다.
- **시스템 트레이**: 시스템 트레이가 화면 상단으로 이동한다. 시계 트레이와 날짜 트레이, 빠른 설정창, 입력기 전환, 숨겨진 앱 보기 토글은 우측 상단에 위치하며, 알림 센터와 배터리 표시만 별도로 좌측 상단에 위치한다. 시스템 트레이의 배경은 완전히 투명해 비쳐보이나, 배경색에 따라 자동으로 텍스트 색상이 검정색, 회색, 흰색으로 조절되기에 시인성을 챙길 수 있다. 각 시스템 트레이 모듈은 독립된 버튼으로 간주되기에, 개별적으로 클릭 / 호버 이벤트를 호출시킬 수 있다.
- **앱 내부 버튼**: WinUI 3의 기본 버튼 형태가 기존 창의 배경과 동화된 형태에서 플로팅 버튼으로 변경된다. 별도의 레거시 버튼 UI 요소가 생겨 기존의 버튼 또한 사용할 수 있다.

Bubble UI에는 아래 문단에서 서술할 Mist 효과가 적용되며, 창의 배경인 Mica 효과와 구분되어 시인성이 향상된다.

### Mist 재질

---

Fluent Desgin에 새로운 재질인 Mist가 추가된다. Mist는 한마디로 모바일 앱 등지에서 자주 보이는 실시간 블러 효과이다. 바탕화면을 비추는 Mica / Mica Alt, 그리고 플라스틱 아크릴 판과 유사한 형태의 Acrylic과는 차별화되며, 투명도가 낮고 강도 높은 실시간 블러가 입혀지며 바로 아랫층의 요소를 비추게 된다. 다만 실시간 블러의 특성 상 기존 3가지 재질보다는 리소스의 사용량이 많음으로, Msit 효과는 Bubble UI가 적용된 대부분의 버튼 및 레이블, 그리고 작업 표시줄에 한정되어 사용된다.

## 기능성 / UX

---

### Windows Copilot Agent

---

Windows Copilot에 OpenClaw를 기반으로 한 Agent 기능이 본격적으로 활성화된다. 최근 파일 검색 등의 단순한 작업만을 수행하던 Windows Copilot이었으나, OpenAI로 영입된 OpenClaw의 기술 제공을 통해 진정한 Agent 역할을 수행하게 된다. [^1] 만약 기기에 NPU가 탑재되어 있다면 NPU를 통해 로컬에서 AI가 실행되며, NPU가 없거나 최소 요구 사항을 충족하지 못한다면 GPU, 그마저도 전력 소모량 등지의 효율성이 떨어진다면 OpenAI의 클라우드 서버 (주로 Azure)를 사용하게 된다.

### Windows Launcher

---

작업 표시줄 시작 버튼 옆에 위치했던 작은 검색 상자가 화면 하단에서 사라지는 대신, Windows Launcher라는 이름으로 재탄생한다. Windows Launcher는 PowerToys Run 묘듈의 소스 코드를 기반으로 하며, Windows Copilot Chat / Agent의 호출, Direct Console 기능이 통합되어 있다. Direct Console이란 별도의 터미날 창을 열지 않고 Launcher 즉석에서 명령어의 실행 결과를 보여주는 기술을 뜻한다.

앱 실행 중이 아닐 시 화면 상단 가운데에 작은 레이블 형태로 존재하는 Windows Launcher는, 마우스가 호버될 시 양옆으로 펼쳐지는 애니메이션과 함께 긴 알약 형태의 바로 변한다. 이것을 클릭한다면 Mist 효과가 적용된 PowerToys Run과 유사한 메뉴가 Launcher 하단에 나타난다. PowerToys RUn과 달리 접두사 없이도 정규 표현식과 Copilot의 자동 인식을 통해 기존의 검색 상자처럼 자동으로 명령을 인식하여 알맞은 기능을 실행한다.

레이블이 화면을 가리는 것을 방지하기 위하여 앱의 최대화 / 타일링 시 Launcher는 화면 상단의 제스처 막대 형태로 변하며, 해당 막대를 클릭하거나 끌어 내려 Windows Launcher를 호출할 수 있다. 이외에도 Win+Space 단축키로도 호출할 수 있다.

[^1]: OpenClaw란 이메일 작성, 코딩, 오피스 업무 등 실제 업무까지 이어질 수 있도록 설계된 개인 개발자의 프로젝트이다. GitHub에서 최단 시간 동안 가장 많은 스타를 받은 프로젝트로도 알려져 있다. 현재 OpenClaw의 개발자 는 OpenAI로 영입되었으며, OpenAI는 MS Copilot의 내부 모델 공급사이기에 Windows Copilot에 OpenClaw의 기술 / 개념이 통합될 가능성이 충분하다 판단하여 기재하였다.
