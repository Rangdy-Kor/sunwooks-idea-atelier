# LUCID

---

> [!IMPORTANT] Lucid Utility, Creative Intuitive Decoration

## 철학

---

HTML을 몰라도 그에 준하는 글쓰기를 할 수 있도록, GFM이 지향했던 수요의 존중을 이어받도록.

## 규칙

---

1. GFM을 기반으로 하고 동시에 포괄하는 상위 호환 문법이어야 한다. 단, 현대 웹 환경 및 Markdown 사용 환경에서 대다수의 사용자들이 혼란스러워하거나 충분한 수요가 존재하는 사항은 초기 GFM이 줄바꿈 문법에서 그랬던 것처럼 GFM 명세에서 수정하였다.
2. Pandoc 등 다른 Markdown 확장 문법과의 호환성은 목표로 하지 않는다.
3. 문법의 토큰을 정할 때는 입력 접근성이 높으며 같은 기호가 반복되는 토큰을 우선시한다.

## 문법

---

### 구조

---

- **줄바꿈** (`<br>`): 개행 문자 한 번으로 입력한다. 현재의 GFM 명세와 어긋나는 부분이나, 이는 개발자가 아닌 대다수의 현재 Markdown 사용자들이 혼란스러워 하는 부분 중 하나기에 수정하였다.
- **단락 바꿈** (`<p>`): 개행 문자 두 번으로 입력한다.
- **이스케이프**: 역슬래시 (`\`) 한 번으로 입력한다. 리터럴 역슬래시는 역슬래시 두 번으로 입력할 수 있다.
- **주석**: 물음표 (`?`) 두 번과 공백 하나로 인라인 텍스트를 감싸거나 (`?? {Content} ??`), 코드 블록처럼 물음표 세 번으로 단락을 열고 닫아 적용한다. HTML을 모르는 사용자들도 주석을 사용할 수 있도록 하기 위해 고안되었다. 인라인 주석을 사용할 시 토큰과 텍스트 사이의 하나의 공백은 필수이다.
- **중첩**: 문법의 중첩은 바깥쪽의 문법이 안쪽의 문법을 포함하는 구조이다. 예를 들어 글자 색상 문법 안에 밑줄 문법이 있다면 밑줄에도 색상이 적용되나, 반대의 경우는 기본 색상 (주로 검은색)이 유지된다.

### 형태

---

**볼드**

```
**{Content}**
```

`{Content}`에 볼드 (굵은꼴) 서식을 입힌다.

**이탤릭**

```
*{Content}*
```

`{Content}`에 이탤릭 (기울임꼴) 서식을 입힌다. 별표 (`*`)를 3개 입력할 시 볼드와 이탤릭이 동시 적용된다.

**취소선**

```
~~{Content}~~
```

`{Content}`에 취소선 서식을 입힌다.

**밑줄**

```
~{Content}~
```

`{Content}`에 밑줄 서식을 입힌다.

밑줄 문법의 토큰을 물결표로 사용할 시 취소선과 파싱 단계에서 혼동될 수 있다는 주장이 많이 거론되나, 이에 대해서는 볼드와 이탤릭 문법이 같은 별표 (`*`)를 사용한다는 선례가 존재한다. 별표를 3개 입력할 시 볼드와 이탤릭이 같이 적용되듯이, 물결표를 3개 입력하더라도 취소선과 밑줄이 동시 적용된다. 밑줄이 하이퍼링크와 혼동될 수 있다는 점은, 2014년 당시와 달리 현재 웹 환경에는 색상, 인터랙션 등 밑줄이 아니더라도 하이퍼링크임을 알아낼 수 있는 요소가 충분하기에 하이퍼링크와 밑줄을 충분히 구별할 수 있으리라 판단하였다.

흔히 발생할 수 있는 착오와 달리 GFM의 명세서에는 단일 물결표를 사용하는 문법이 존재하지 않는다. Pandoc 등의 GFM을 제외한 다른 문법과는 호환성을 고려하지 않았다는 점을 명시한다. GFM에서 물결표 3개로 코드 블록 문법이 작동하는 것에 대해서는, 별표 3개가 수평선으로 작동하는 선례가 존재하기에 토큰이 동일한 블록과 인라인 문법을 다르게 해석하는 설계를 유지해왔다는 점을 고려해야 한다. 코드 블록은 수평선과 달리 토큰 뒤에 문자열을 추가할 수 있다는 점이 있으나, 이 또한 행의 끝에서 닫는 구조와 완전히 다르기에 한 단계의 전방 탐색이나 상태 확인으로도 두 문법을 분리할 수 있다.

**위 첨자**

```
^^{Content}^^
```

`{Content}`에 위 첨자 서식을 입힌다.

캐럿 (`^`) 기호는 수학계에서 거듭제곱을 표현할 때 사용하는 기호와 모양이 동일하며, 위 첨자를 시각적으로 연상시킨다는 특징이 있다. 이러한 점 때문에 위 첨자의 토큰을 캐럿 기호로 채택하였다. Pandoc 등 타 문법에서 캐럿 기호를 다른 용도로 사용하는 경우가 존재하나, LUCID는 GFM과의 호환성만을 고려하였다.

**아래 첨자**

```
,,{Content},,
```

`{Content}`에 아래 첨자 서식을 입힌다.

단일 쉼표는 자연어에서 흔하게 사용되는 기호이나, 다중 쉼표는 대부분의 자연어에서 사실상 사용되지 않는 형태이다. 이에 더해 쉼표는 일반적인 문자들의 기준선보다 아래에 위치하기에 아래 첨자라는 서식을 시각적으로 연상시킨다.

**스포일러**

```
##{Content}##
```

`{Content}`를 흐리게 처리한 후, 마우스 커서가 호버 중이거나 모바일 환경에서 터치할 시 원본 텍스트를 보여준다.

해시 (`#`)는 GFM에서 헤딩에 사용되는 기호이나, 이는 토큰 뒤의 공백 여부, 그리고 닫는 토큰의 존재 여부로 전방 탐색을 통해 충분히 구현할 수 있다. 더불어 해시는 시각적으로 특유의 격자 모양이 모자이크를 연상시키는 면이 존재하기에 스포일러의 토큰으로 사용하였다.

**리터럴**

```
""{Content}""
```

`{Content}`에서는 LUCID 문법이 적용되지 않고 문자열 그대로를 출력한다. 이스케이프와 달리 여러 문자에 리터럴을 적용할 수 있으며, 코드 블록과는 달리 고정폭으로 출력되지 않는다.

```
"""
{Content}
"""
```

위와 같이 코드 블록처럼 큰따옴표 (`"`) 세 번으로 단락을 열고 닫아 하나의 단락을 리터럴 처리할 수 있다.

### 색상

---

**글자 색상**

```
++{ColorCode} | {Content}++
```

`{Content}`에 `{ColorCode}`에 기재된 색상을 적용한다.

`{ColorCode}`에는 헥스 코드, 단축 헥스 코드, 알파 헥스 코드, 단축 알파 헥스 코드, CSS 색상명 140가지 중 하나, 그리고 CSS 변수명을 입력할 수 있다. 헥스 코드 패밀리에는 접두사로 해시 (`#`)이 필수적으로 요구되며, CSS 색상명에는 선택적으로 입력할 수 있다. 반면 CSS 변수명에는 접두사로 하이픈 (`-`) 두 개를 필수적으로 요구한다.

```
++{LightModeColorCode}, {DarkModeColorCode} | {Content}++
```

위와 같이 두 종류의 `{ColorCode}`를 쉼표로 구분하여 라이트 모드와 다크 모드에서 적용되는 색상을 구분할 수 있다. 각각의 색상 코드는 서로 다른 형식을 사용할 수 있다.

`{ColorCode}`와 `{Content}`를 구분하는 수직선 (`|`) 문자는 표에서도 사용되기에, 표 내부에서 수직선 들어가는 문법들 (글자 색상, 하이라이트, 크기 조절 등)을 사용할 때 레이아웃이 깨질 우려를 표할 수 있다. 이는 하나의 셀 내부에서의 우선 순위를 조정하여 해당 문법들 내부의 수직선은 표 계산에서 제외하는 로직으로 해결할 수 있다.

**하이라이트**

```
=={ColorCode} | {Content}==
```

`{Content}`의 배경에 `{ColorCode}`에 기재된 색상을 적용한다.

`{ColorCode}`에 입력될 수 있는 코드 형식의 종류와 접두사 규칙, 라이트 모드와 다크 모드의 구분, 표 내부에서의 파싱 우선 순위 문제에 대해서는 위의 글자 색상 문법을 참고하기 바란다. `{ColorCode}`가 생략될 시 하이라이트 색상의 기본값은 헥스 코드로 `#f7e491`이다.

### 크기

---

**글자 크기**

```
%%{Value}{Unit} | {Content}%%
```

`{Content}`의 글자 크기에 `{Unit}`에 따른 단위와 `{Value}`에 기재된 수치를 적용한다.

`{Value}`에는 일반적인 Float형 수치가 입력될 수 있으며,`{Unit}`으로는 `rem`, `em`, `px`을 사용할 수 있다. `{Unit}`이 생략될 경우의 기본값은 `rem`이다. `{Value}`와 `{Unit}` 사이의 공백은 선택적으로 허용되며, 권장값은 존재하지 않는다.

백분율 (`%`) 기호는 해당 기호의 역할 상 크기를 연상시키며, GFM에서 역할이 지정되지 않은 비어있는 기호이기에 크기 문법의 토큰으로 사용하였다.
