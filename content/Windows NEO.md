# Windows NEO

---

개인적으로 원하는 Windows의 최종 진화형

## 디자인

---

**Noto Font 통일**:

- 운영체제의 기본 글꼴이 다국어 지원의 일관성을 위해 Google의 Noto 시리즈로 통일된다.
- 기존에 사용되던 레거시 글꼴 (맑은 고딕, Segoe UI 등)은 Fallback 글꼴로서 하위 호환성을 위해 유지되나, 더 이상 기본 글꼴로는 사용되지 않는다.
- 기본 시스템과 인터페이스에는 Noto Sans, 워드프로세서 등의 문서에는 Noto Serif, 터미널과 IDE / 에디터에는 Noto Sans Mono[^1]가 기본값으로 사용되거나 권장된다.

**LucidType**:

- FHD 이상의 고해상도 모니터에서 적용되는 디스플레이 글꼴 가독성 향상 기술이 그 효과를 증폭 시키기 위해 차세대 LucidType으로 교체된다.
- 기존 ClearType은 RGB 서브 픽셀 렌더링을 사용하기에 RGB 픽셀 배열의 LCD 모니터에 최적화 되어있었고, 현재 대중화된 LED 기반 / 비 RGB 배열의 모니터에서는 유의미한 효과를 보이지 못하거나 오히려 역효과를 불러 일으켰다.
- 이에 더불어 새롭게 도입되는 Noto Font와의 궁합 또한 좋은 평가를 받지 못하는 ClearType이었기에, 새로운 가독성 향상 기술이 필요한 시기였다.
- 때문에 LucidType은 ClearType가 달리 차세대 그레이스케일 안티 앨리어싱 기술을 사용하며, 사용자의 모니터 해상도와 DPI를 자동 감지하여 동적으로 그 강도가 조절된다. 픽셀 배열 방식의 경우에 한해 선택적인 사용자의 수동 조정이 필요하다.
- 허나 HD 이하의 해상도, 혹은 기준치보다 낮은 DPI 모니터라면 여전히 ClearType이 자동으로 적용된다. 또한 사용자는 설정 앱의 _개인 설정 => 글꼴 => 관련 설정 => 가독성 향상 기술_ 옵션에서 레거시 가독성 향상 기술을 선택함으로서 ClearType으로 되돌아갈 수 있다.

**Bubble UI**:

- 대다수의 일반 사용자들이 기존의 평면적인 UI에서 심미적으로 만족하지 못한다는 점을 해결하기 위해 Fluent Design에 새로운 디자인 형태인 Bubble UI가 추가된다.
- Bubble UI는 다른 인터페이스의 위에 레이어 방식으로 더해져 입체감과 시인성을 향상시키는 원형 / 알약 형태의 UI이다.
- **적용 범위와 사례**:
  - **창 조절 버튼**: 제목 표시줄에 통합되어 있던 창 조절 버튼이 플로팅 원형 버튼 형태로 변화한다. 특정 트리거 (호버 효과 등)을 거치치 않고도 기존과 같이 클릭만으로 창을 조절할 수 있다. 또한 시각적인 형상만이 변경되었으며, 상호작용 범위는 기존과 동일한 정사각형 범위이기에 사용자에게 근육 기억의 혼선으로 인한 불쾌감을 유발하지 않는다.
  - **작업 표시줄**: 화면 하단의 전체 너비를 차지했던 작업 표시줄이 플로팅 알약 바 형태로 변화한다. 후술하겠지만 검색 상자와 시스템 트레이, 위젯 버튼은 작업 표시줄에서 독립하나, 예외적으로 바탕화면 보기 막대는 혼란을 막기 위해 최우측 하단 자리를 유지한다. 창이 최대화되거나 타일링될 시 작업 표시줄은 애니메이션과 함께 좌우로 확장되며 기존의 작업 표시줄 바처럼 변화한다. 이는 양측 공백에 비쳐 보이는 바탕 화면에서 심리적으로 시각적인 불안정함을 느끼는 사용자가 존재한다는 점에서 고안되었다. 해당 효과는 설정 앱의 _개인 설정 => 작업 표시줄 => 창의 최대화 및 타일링 시 작업 표시줄 확장_ 옵션에서 비활성화할 수 있다.
  - **앱 내부 버튼**: 창의 배경과 동화된 형태였던 WinUI 3의 기본 버튼에도 Bubble UI가 적용된다. 별도의 레거시 버튼 UI 또한 지원된다. 허나 WinForms / WPF / UWP는 기본적으로 Bubble UI를 지원하지 않는다.

**시스템 트레이 이동**:

- 작업 표시줄에 부속되어 있던 시스템 트레이가 대화면 모니터의 활용과 화면 하단에 중심되어 있는 시선을 분산 시키기 위하여 화면 상단으로 이동한다.
- 시계 및 날짜 트레이와 빠른 설정창, 입력기 전환, 숨겨진 아이콘 표시 토글은 우측 상단에 위치하며, 알림 센터와 배터리 표시 아이콘은 좌측 상단에 위치한다.
- 시스템 트레이는 완전히 투명한 배경을 사용한다. 허나 이로서 발생하는 배경과의 시인성 확보 문제를 이를 해결하기 위해 텍스트 색상과 테두리 색상은 바탕 화면의의 휘도와 대비를 기반으로 동적으로 조정된다.
- 각 시스템 트레이 모듈은 독립적인 버튼으로 위치하기에 개별적으로 클릭 / 호버 이벤트를 호출할 수 있다.
- 해당 변경 사항은 설정 앱의 _개인 설정 => 작업 표시줄 => 작업 표시줄 항목 => 클래식 트레이 아이콘_ 옵션에서 되돌릴 수 있다.

**Mist 재질**:

- 기존의 Mica / Mica Alt / Acrylic 재질이 사용자의 심미적인 만족도를 충족시키지 못하였다는 판단 하에 Fluent Design에 새로운 재질은 Mist가 추가된다.
- Mist는 하단 레이어의 요소를 고밀도의 실시간 블러로 비추는 재질이다. 때문에 바탕화면만을 비추는 Mica / Mica Alt와, 플라스틱 아크릴 판을 모방한 저밀도의 Acrylic과는 차별화된다.
- 실시간 블러의 효과의 특성 상 기존 재질보다 시스템 리소스 사용량이 증가하기에, Mist는 Bubble UI가 적용된 요소와 기타 특정 포인트 요소에 한정되어 사용된다.
- Mist 재질 효과는 설정 앱의 _개인 설정 => 색 => 실시간 블러 효과_ 옵션에서 비활성화 할 수 있다.

## 기능성

---

**Windows Copilot Agent**:

- 기존 Windows Copilot의 제한적인 Agent 기능이 사용자의 실제 작업에 큰 영향력을 끼치지 못한다는 점을 해결하기 위하여 Copilot에 본격적인 중앙 집중 AI Agent 기능이 추가된다.
- Windows Copilot Agent라는 모델이 추가되며, 해당 모델은 OpenClaw[^2] 프레임워크와 GPT 모델을 기반으로 한다.
- Windows Copilot이라는 시스템 구성 요소에 종속된 모델이기에 일부 작업 시 관리자 권한의 허용을 사용자로부터 UAC를 통해 요구 받으나, 이는 Windows Copilot 자체의 권한을 상승 시켜 해결할 수 있다.
- 만약 기기에 NPU가 탑재 되어 있다면 로컬 기기에서 Copilot Agent가 실행되며, NPU가 없거나 최소 요구 사항을 충족하지 못할 경우 기기 내부의 GPU, 그마저도 전력 소모량 등 충분한 효율성을 발휘하지 못한다면 OpenAI의 클라우드 컴퓨팅 자원 (주로 MS Azure)에서 실행된다.

**Windows Launcher**:

- Windows Copilot의 접근 경로를 형성하고 기존 검색 상자의 낮은 사용률을 보완하기 위하여 검색 상자가 Windows Launcher라는 이름으로 새롭게 탄생한다.
- Windows Launcher는 PowerToys Run 모듈의 소스 코드를 기반으로 하며, Windows Copilot Chat / Agent 호출, 그리고 Direct Console 기능이 통합되어 있다. Direct Console은 별도의 터미널 에뮬레이터 창 없이도 Windows Launcher 자체에서 명령 체인의 출력 결과를 보여주는 기능을 뜻한다.
- PowerToys Run과 달리 별도의 접두사 없이도 입력 파싱과 Copilot의 문맥 인식 기능을 통해 수식 및 명령어, 혹은 자연어만으로 자동으로 명령을 인식하여 알맞은 기능을 수행한다.
- Windows Launcher는 어떠한 앱도 실행 중이지 않거나 바탕 화면 보기 상태일 시 화면 상단 중앙에 작은 알약 형태의 레이블로 존재한다. 이 레이블에 마우스를 호버 시킬 시 애니메이션과 함께 양측으로 확장되며 긴 바 형태의 상자로 변화한다. 이 상자를 클릭하면 Mist 재질이 적용된 하단의 모듈에 최근 및 연관 결과가 PowerToys의 PowerToys Run 및 명령 도구 모음과 유사하게 나타난다.
- 레이블이 화면의 중심부를 차지하여 시인성을 하락 시키는 것을 방지하기 위해 앱의 최대화 / 타일링 시 화면 상단의 제스처 막대로 변화한다. 해당 막대를 클릭하거나 끌어 내려 Windows Launcher를 호출할 수 있다.
- Alt+Space 단축키를 통해서도 Windows Launcher를 호출할 수 있으며, 본래 Alt+Space에 할당되었던 마우스가 보급되기 이전의 유산인 창 제어 호출 메뉴는 Shift+Alt+Space로 대체된다.

[^1]: [Google Fonts](https://fonts.google.com) 홈페이지에서는 대표 다국어 문자들 (라틴 문자, 키릴 문자 등)만 포함된 Noto Sans Mono가 게시 되어있으나, 공식 GitHub 저장소에서는 Noto Sans Mono CJK 또한 배포되고 있다.

[^2]: [OpenClaw](https://github.com/openclaw/openclaw)는 다른 AI 모델이 이메일 작성, 코딩, 오피스 업무 등 실무 상의 연쇄적인 의사결정 작업까지 가능하도록 하는 자율 AI Agent 프레임워크이다. 현지 시각 2025년 11월 24일 출시 이후 GitHub에서 역대 최단 기간에 가장 많은 스타를 받으며 React의 기록을 갱신한 프로젝트로 알려져 있다. 현재 OpenClaw의 개발자 피터 스타인버거는 OpenAI로 영입된 상태이며, OpenAI는 MS Copilot의 내부 모델 공급사이기에 OpenClaw의 기술이 제공될 가능성이 충분하다 판단하였다.
